# Proposal — Import, modes, any resolution, optimized media, setup

**Revision 2 (2026-09-26), with the owner's decisions applied. Status: PLAN. Nothing is
applied yet.** Measurements come from release builds on the Mac Studio (M1 Max) using
`selfqa decode` on synthetic test footage. Anything not measured is labelled
*estimate* or *unverified*.

### Decisions (from review)
| Question | Decision |
|---|---|
| Scope | **Include multiple resolutions and frame rates now.** Amend CLAUDE.md, SPEC and BUILD-PLAN (§1). |
| Mode shortcuts | **⌘1 Import · ⌘2 VJ · ⌘3 Settings** (§4). |
| Optimize | Enabled on **Copy** only (Add/Move grey it out). **Linked, Resolve-style** (revised after review): the original stays the library's clip; the optimized file goes to the **Optimized Media location** and is linked to it in the catalog; playback uses it when present (§5, §7). |
| Default canvas | **SD NTSC 720×480 @ 29.97** stays the default. |
| Tags | **Deferred to 0.5.0** (appendix A keeps the design). |
| Catalog | **SQLite, a single catalog file, as in Lightroom Classic** (§3). |

## 0. The short version

1. **Large imports freeze Videoboy because all of the work runs on the main thread**:
   a synchronous folder walk, a synchronous poster decode per tile (33 ms per HD clip,
   141 ms per .m2v), and a full library rebuild per measured clip. **Fix that first**:
   a background import job plus the contextual status bar (§2).
2. **The library is not saved today.** Clips, bins and in/out marks are lost at quit.
   An SQLite catalog is the foundation for everything below (§3).
3. **Which clip style performs best, measured: resolution matters far more than codec, and
   keyframe spacing sets the worst case.** Optimized clips are written at the canvas size
   and frame rate: **DV** on the SD NTSC canvas, **MPEG-2 GOP 6 without B-frames**
   everywhere else. Both keep the bitstream wedge (§7).
4. **Any resolution builds on a seam that already exists** (`RenderContext` carries the
   size). It must follow the decode fixes and carry an automatic ½-resolution fallback
   so a show never stutters (§6).
5. **~13k lines, 6 phases, roughly 17.5M input / 0.9M output tokens (±50%).** Opus
   specs and keeps the frame-path work; Sonnet builds the UI and plumbing (§10).

## 2. Big imports: the background job and the contextual status bar

### What happens now (from the code and the 09-26 audit)
| Stage | Where | Cost |
|---|---|---|
| Walk dropped folders (`itemsWalking`) | main thread | grows with file count (*estimate*: seconds for a large tree) |
| Poster frame per new tile (`LibraryItemView.loadFrame`) | main thread | SD 4–13 ms, HD 24–34 ms, 4K 89 ms, **.m2v 18–141 ms**, 60 s DV 36 ms (measured) |
| Per-clip duration → `fillDurations()` + `notify()` | main thread | N full rebuilds for N clips |
| Thumbnail cache | memory | no size limit |

### The fix (Phase 1)
- The import job **walks, probes and measures on a utility queue**. Results merge into
  the catalog and library in **batches** (at most ~4/s), with one rebuild per batch.
- **Thumbnails off the main thread**: a placeholder, then the picture. One decoder per
  clip serves all 12 hover steps, and the cache is LRU-capped at ~64 MB.
- **Throttled while a show is live**: with the transport running or output on air,
  the job runs one file at a time at background priority.

### The contextual status bar
It appears **only when the context calls for it**: the import includes a folder, **or**
has more than 5 clips, **or** runs longer than ~2 s. It hides ~3 s after finishing. It
lives **inside the existing bottom strip's left segment** and never moves the grid or a
control.

```
┌──────────────────────────────────────────────────────────────────────────────────────┐
│ ⟳ IMPORT  ▸ Reel B / CLIP0042.MOV  ▣ Reel B ⁴⁸  ▣ Reel C ¹²   37 / 212  ▓▓▓▓░░░  ✕ │ ⬇ IMPORT ▦ VJ ⚙ SETTINGS │ MIDI · drop 0 · 29.97
└──────────────────────────────────────────────────────────────────────────────────────┘
```
- **Flashing names**: the file being worked on, updated at most ~8×/s, in monospace so
  the bar never reflows.
- **Folders**: one chip per folder (folder icon, name, clip count). The active folder's chip
  pulses. More than 3 folders collapse to "▣ 9 folders".
- **Stages**: *Scanning… 212 found* → *Adding* → *Reading* (durations, posters) →
  *Copying* / **Optimizing 12 / 48** (Copy imports) → *Done — 212 added · 3 unreadable*.
  Clicking "unreadable" lists the files and their reasons.
- **✕ cancels** safely. Finished clips stay, and a half-written copy is deleted (§5).
- Clicking the bar opens Import mode's activity list.

## 3. The foundation: the catalog (SQLite, Lightroom-style)

- **One catalog file** (`Videoboy Catalog.vbcatalog`) in the **Library location** chosen
  at setup, as with Lightroom Classic's catalog. It's one file to back up or move, and it
  is locked while open so two copies of the app can't write to it.
- **System `libsqlite3`** (`import SQLite3`): no new dependency.
- **Contents**: clips (stable UUID, file **bookmark** plus path, size, modification date,
  content hash for duplicate detection, codec, resolution, frame rate, **frame
  count**, duration), **in/out marks**, bins, colour label, import history, and a
  schema version. **Tags arrive in 0.5.0 as a migration.**
- **The same record everywhere**: an in/out mark set on an Import tile **is** the mark the
  VJ library shows. The library UI becomes a view onto the catalog. This also closes the
  audit's L5 (clips identified by name).
- **Bookmarks, not bare paths**: a clip survives its folder being renamed or moved. A
  missing file shows offline with **Relink…**.
- **Measured once**: frame count and duration are stored at import, which removes the `.m2v`
  open-time scan (it grows with length: **130 ms for 60 s, ~1.3 s for 10 min, on the
  main thread, measured**).
- **Safety**: WAL mode and a single writer queue off the main thread. There's an automatic
  backup on quit (weekly by default, as Lightroom does) and **File ▸ Export Catalog as
  JSON** for inspection.

## 4. The mode bar and modes

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ [import status | MIDI · OSC · drop · fps]   ⬇ IMPORT   ▦ VJ   ⚙ SETTINGS   [routing] │
└──────────────────────────────────────────────────────────────────────────────┘
```
- It's Resolve's page bar, **merged into the existing status strip**. The strip grows
  from ~20 to ~32 pt, which shrinks the grid once (approved in §1). It has room for 5 modes.
- **⌘1 Import · ⌘2 VJ · ⌘3 Settings**, as **View-menu items** with key equivalents, so
  they're discoverable and remappable in System Settings ▸ Keyboard. Checked: no ⌘-digit
  binding exists in the app today (the library uses ⌘↑ ⌘↓ ⌘⌫). This also avoids the
  Shift-arms-MIDI-learn clash the ⇧-digit version had. ⌘, still opens Settings.
- **Switching modes never interrupts output**: the engine keeps rendering, and output
  and recording continue. VJ's previews stop presenting while hidden (the existing P7
  machinery).
- **Settings mode** gathers today's Preferences panes plus **Project** (canvas and frame
  rate), **Media** (locations) and **Optimize** (presets).

## 5. Import mode (Lightroom Classic model)

```
┌─ SOURCES ─────────┬─ VIEWER (double-clicked clip) ──────────────┬─ IMPORT ───────────────┐
│ ▾ Devices         │ ┌───────────────────────────────────────┐   │ [ ADD | MOVE | COPY ]  │
│   Macintosh HD    │ │   letterboxed to the canvas shape     │   │                        │
│   SD card  ⏏      │ └───────────────────────────────────────┘   │ ▾ Destination          │
│ ▾ Network         │  ⏮ ◀◀ ◀ ▶ ▶▶ ⏭  I  O  ⟲   00:00:12:04        │   ~/Movies/Videoboy/…  │
│   studio-nas      │─────────────────────────────────────────────│   ☐ Into subfolder …   │
│ ▾ iCloud Drive    │  All ▾  New ▾  In library ▾   ☑ All ☐ None  │   Organize: by folder ▾│
│ ▾ Favorites  +    │  ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐        │ ▾ Optimize media       │
│   Tapes/          │  │☑ ▓▓▓ │ │☑ ▓▓▓ │ │☐ ▓▓▓ │ │☑ ▓▓▓ │        │   ☑ Optimize while     │
│   Phone dumps/    │  │ I──O │ │      │ │ DUP  │ │ ⚠16:9│        │     copying            │
│ ▾ Locations       │  └──────┘ └──────┘ └──────┘ └──────┘        │   Preset: Performance ▾│
│   Movies          │  CLIP0041  CLIP0042  CLIP0043  CLIP0044     │   → DV · 720×480 · 29.97│
│   Desktop         │  ☑ Include subfolders     size ●────        │ ▾ Into bin: Reel B ▾   │
│   Downloads       │                                             │   ☑ Skip duplicates    │
│                   │                                             │  [ Cancel ] [ Import 3 ]│
└───────────────────┴─────────────────────────────────────────────┴────────────────────────┘
```

**Sources (left)**: mounted volumes, with eject for removables. Mounted network
shares; unmounted servers go through "Connect to Server…" (Finder). **iCloud Drive**,
where files not yet downloaded get a cloud badge and are downloaded before import.
**Favorites**: our own list (macOS has no public API for Finder's sidebar). Movies,
Desktop, Downloads. The first access triggers macOS's privacy prompts, which is expected.

**Media grid (centre)**: large versions of the VJ library tiles: hover-scrub, **I/O marks
stored in the catalog**, and a checkbox. Check All/None; filters for All / New / Already in
library (duplicates greyed with a DUP badge); size slider; sort. Badges for format,
**wedge-ready** (DV/MPEG) and **canvas mismatch** (⚠16:9 on a 4:3 canvas, ⚠ vertical).

**Viewer**: a double-click loads the clip, with shuttle, frame step, I/O, loop and J/K/L,
letterboxed to the canvas shape. Collapsible (V). **Its player is separate from the
engine's channels**, so auditioning never touches the program. Low priority, and 15 fps
while a show is live.

**Right pane, Add / Move / Copy** (Lightroom's meanings: *Add* catalogs files in place;
*Move* moves them to the destination; *Copy* copies them and leaves the originals).
Controls are **greyed, not hidden**, so nothing shifts under the pointer:

| | Destination | Optimize |
|---|---|---|
| ADD | disabled | disabled |
| MOVE | enabled | disabled |
| COPY | enabled | **enabled** |

Also, **Move is disabled for read-only, removable, network and iCloud sources**
(Lightroom disables Move and Add for cards).

### Copy + Optimize: linked optimized media (Resolve model)
The original is copied to the destination and **stays the library's clip**: its marks,
bins and (from 0.5.0) tags live on it. The optimized version is written to the **Optimized
Media location** and **linked to it in the catalog** (one reason for SQLite). One clip,
two files.
- **Playback ▸ Use Optimized Media If Available** (default on): the engine plays the
  optimized file. Switch it off to play originals. A badge on the tile says which is playing.
- **Written safely**: to `.videoboy-partial/`, renamed into place only when complete. The
  link is recorded only then.
- **Marks are stored as time**, so they apply identically to both files, even when the
  optimized one was conformed to the canvas frame rate.
- **Canvas changes are recoverable**: optimized files record the canvas they were made
  for. After a canvas change, stale ones are flagged and **Re-optimize** rebuilds them from
  the linked original.
- **Relink** works for originals and optimized files independently. A missing optimized
  file falls back to the original, never to black.
- A failed conversion leaves the clip playing its original, and is reported.

## 6. Any resolution and frame rate: architecture and performance

### Canvases (Settings ▸ Project, and setup)
**SD NTSC 720×480 (default)** · SD PAL 720×576 · **HD 1920×1080** · **Square
1080×1080** · **Vertical 1080×1920**. Frame rates: **29.97 (default)**, 30, 25, 24,
23.976. 50/59.94 halve the budget to 16.7 ms; defer them.

### What changes
- **Seam present**: `RenderContext` already carries `width`/`height`, and most effects size
  their targets from their input.
- **`StandardDefinition` → `ProjectFormat`** (width, height, frame rate, pixel aspect,
  interlace). There are 39 size references in 14 files, 37 frame-rate references and 16
  literal 720/480s. The content clock (`contentFrameDue`) reads the project rate. Done by
  script, reviewed.
- **Sources are fitted to the canvas** (fit / fill / stretch per clip: Resolve's
  "mismatched resolution" options), on the GPU during upload.
- **SD-native nodes stay SD inside** (DV bus codec and emulation, NTSC composite codec,
  DV sources), with GPU scale-in and scale-out adapters on other canvases. The DV wedge
  works at SD detail, scaled; the MPEG wedge works at any size.
- **Previews stay 4:3**, drawn *fit, never deformed* (existing `PreviewFill.fit`). A
  vertical canvas pillarboxes to ~42% of the width.
- **Analog output framing**: Output ▸ Framing offers fit, fill (centre crop) and stretch
  into the 4:3 SD signal.

### Keeping "never stutter" at HD
HD is **6× SD's pixels**. The GPU fence at SD is 1.4–2.8 ms (measured), so *estimate*
**8–17 ms at HD**. Texture memory is 138 MB at SD (measured), *estimated* **~830 MB at HD** and
~470 MB square. Six live 1080p H.264 datamosh encodes exceed the hardware encoder.
1. **Decode fixes first** (Phase 0). HD soak today: every tick over 16 ms, 75 ms worst.
2. **Datamosh runs at SD or 720p internally** and is scaled.
3. **Echo and feedback history sized in seconds**, capped per canvas.
4. **Automatic ½-resolution fallback** when frames near the budget, announced in the
   status bar (the idea behind Resolve's proxy mode).
5. **Gates**: `stress` and `soak` per canvas, on real HD footage.

## 7. Optimized media: which clip style performs best (measured)

Same synthetic source, 4 s clips (so each run loops once), current pipeline, release
build, per channel, on the main thread:

| Format | Canvas | Steady ms/frame | **Worst** (incl. loop) | MB/min | Wedge effects |
|---|---|---|---|---|---|
| **DV** | SD | 2.2 | **3.8** | 210 | **DV** |
| MPEG-2 intra-only | SD | 1.6 | 4.5 | 190 | MPEG |
| **MPEG-2 GOP 6, no B** | SD | **0.9** | **3.4** | 75 | **MPEG** |
| MPEG-2 GOP 15 | SD | 0.9 | 9.0 | 60 | MPEG |
| H.264 GOP 15 | SD | 1.1 | 11.7 | 50 | none |
| H.264 GOP 60 (camera style) | SD | 1.3 | 15.1 | 50 | none |
| ProRes Proxy | SD | 1.1 | 8.5 | 90 | none |
| MJPEG | SD | 1.1 | 7.7 | 200 | none |
| **MPEG-2 GOP 6, no B** | HD | **3.9** | **14.4** | 225 | **MPEG** |
| MPEG-2 GOP 15 | HD | 3.5 | 14.9 | 170 | MPEG |
| MPEG-2 intra-only | HD | 9.3 | 19.4 | 1,030 | MPEG |
| H.264 GOP 15 / 60 | HD | 5.9 | 22–23 | 110–125 | none |
| ProRes Proxy / LT | HD | 6.3 | 27–35 | 360–790 | none |
| MJPEG | HD | 5.7 | 16.2 | 1,120 | none |

- **Resolution dominates**: converting to the canvas size is most of the gain.
- **GOP length sets the worst case** (loops, seeks, reverse). GOP 6 without B-frames nearly
  matches intra-only at a third of the size.
- **Today H.264, ProRes and MJPEG all cost ~6 ms at HD** because of the CPU copy and swizzle
  (audit F2/F3), not the codec. **Re-run this table after Phase 0.**
- **Only DV and MPEG-2 keep the wedge.**

### Presets (all overridable in setup and Settings)
| Preset | SD NTSC canvas | Any other canvas |
|---|---|---|
| **Performance (default)** | **DV** | **MPEG-2 GOP 6, no B**, ~10 Mb/s SD-PAL / ~30 Mb/s HD |
| Compact | MPEG-2 GOP 6 @ 6 Mb/s | MPEG-2 GOP 12 @ 15 Mb/s |
| Custom | codec (DV · MPEG-2 · ProRes Proxy · H.264 · MJPEG), GOP, bitrate/quality, keep audio (default **off**) | same |

Resolution and frame rate **always follow the canvas**. Frame count is written to the
catalog, so opening never scans.

### 8 GB MacBook Air (*unverified on hardware*; reasoned from measurements)
- **CPU**: same core generation as the M1 Max, so decode should be close: 4 optimized SD
  channels ≈ 4–9 ms.
- **GPU**: 7–10 cores vs 32, so *estimate* 4–10 ms of effects at SD, which is comfortable. **An HD
  canvas on an Air defaults to the ½-resolution fallback.**
- **Memory, the real constraint.** Two fixes are in Phase 0:
  - **`DVReader` reads the whole file into RAM** (`Data(contentsOf:)`): ~209 MB for 60 s
    (measured), ~2 GB for 10 min. Fix: memory-map it (`.alwaysMapped`).
  - Decoder caches sized for the M1 Max (48 AVF / 32 MPEG frames; ~265–400 MB per HD
    channel). Replace them with a small prefetch ring sized by canvas.
- **Disk**: 4 DV channels = 12.5 MB/s. An hour of DV is ~13 GB; show the estimate
  before a big Copy + Optimize.
- **Gate**: one `soak` on a real Air before claiming support.

### How conversion runs (licensing)
The bundled FFmpeg is an **LGPL minimal library** (encodes DV, MPEG-2, MJPEG, raw; no HEVC
or ProRes decode). The plan is a **separate LGPL `ffmpeg` command-line helper** built with the same
license settings, plus decoders (hevc, prores, h264 via VideoToolbox), the
`h264_videotoolbox` and `prores_ks` encoders, and the mpegts/mpeg2video/mov muxers. **No libx264,
nothing GPL.** It runs **out of process** (a crash can't take the show down; cancellable),
at background priority, and pauses while output is live unless allowed. Update THIRD-PARTY.md.

## 8. The setup assistant (first launch, re-runnable from Settings)

A single sheet with pages. Defaults everywhere, so **Continue ▸ Continue ▸ Done** works.
1. **Welcome**.
2. **Locations**: **Save/Templates**, **Plugins** (ISF), **Library** (the catalog file),
   **Media** (the default Copy destination), **Optimized media** (where linked optimized
   files are written). Stored as bookmarks. Checks free space, and warns about slow or network volumes.
3. **Project**: canvas and frame rate, with **SD NTSC 29.97** preselected and one line on why.
4. **Optimize**: preset (Performance / Compact / Custom); codec, GOP and quality under a
   disclosure; a per-hour disk estimate.
5. **Done**: summary, plus *Open Import (⌘1)*.

It replaces today's first-run "pick a templates folder" alert. Changing a location later
offers to move its contents and never deletes anything.

## 10. Token load and the Opus/Sonnet split

**~13k lines. Input ≈ 17.5M tokens (~85–90% prompt-cache reads), output ≈ 0.9M. ±50%.**
Basis: about 1.3k input and 70 output tokens per line shipped in this repo, counting reads,
harness output, iterations and review.

| Phase | Opus spec + review (in / out) | Sonnet build (in / out) | Opus builds itself |
|---|---|---|---|
| 0 decode fixes | — | — | **2.5M / 150k** |
| 1 catalog + import job | 0.4M / 30k | 2.3M / 110k | schema + threading spec |
| 2 mode bar + setup | 0.3M / 20k | 2.3M / 110k | — |
| 3 import mode | 0.5M / 35k | 4.0M / 190k | — |
| 4 copy + optimize | 0.35M / 20k | 1.9M / 90k | license review of the helper build |
| 5 any resolution | 0.6M / 40k | 2.4M / 110k | render adapters, fallback |
| **Total** | **~2.15M / 145k** | **~12.9M / 610k** | **~2.5M / 150k** |

**How to make it efficient:**
1. **One Opus spec per phase** (`docs/specs/phase-N.md`): exact types and signatures, a
   file-by-file change list, threading rules, and the self-QA assertions that define "done".
   Sonnet gets the spec and **the list of files to read**, not a codebase exploration.
   That's the biggest saving.
2. **Sonnet works in its own git worktree per phase** (the tree is shared with other
   sessions). After Phase 1, **phases 2 and 5 can run in parallel**; 3 follows 2, and 4
   follows 3.
3. **Opus keeps the work that breaks quietly**: the prefetch ring, render adapters and
   fallback, the catalog's threading, and the licensing check. It reviews every Sonnet diff
   and runs `stress` and `soak` itself.
4. **Split `ShellController.swift` (3,116 lines) first**, into one controller per mode, so
   every later UI change reads less.
5. **Local `qwen`** (free) for header comments, commit messages, test scaffolding and log
   summaries. The `ProjectFormat` rename (40+ files) is done by script, not by qwen.
6. **One long-lived session per phase** keeps the prompt cache warm. Harness runs go to
   the background and report only their results.

## Appendix A — Tags (deferred to 0.5.0)

Kept for 0.5.0 as proposed: tags with name, colour and group (Mood, Palette, Motion,
Content, Energy 1–5) plus a colour label; automatic tags from the import analysis
(orientation, format/wedge-ready, duration, loop length in beats, dominant colour,
brightness, motion energy, loopable); for mixing, **tag pools** feeding a channel's
up-next queue, **tag pads** on MIDI loading a matching clip into the off-air channel,
**beat shuffle**, and an **energy fader**; smart bins; optional mirroring to Finder tags.
The catalog's schema versioning (§3) makes this a clean migration.
