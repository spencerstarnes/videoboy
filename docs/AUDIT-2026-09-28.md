## Findings

Status: **FIXED** (this session) · **OPEN** (backlog) · **KNOWN** (earlier audit).

### A1 — The app did not build (FIXED, `c5786d9`)

The DV refactor (`ad14e29`) removed Core's DV types but not their App callers: 40
compile errors in 12 files, and 3 Core tests failing. `verify.sh` could not pass.
Finished the removal:

- `AnalogStandard` (NTSC/PAL raster and rate) replaces `DVStandard` for the DVC100
  capture and the four-up tile; it was never about DV.
- The launch screen checks the MPEG-2 decoder (`ClipDecoders.bitstreamCodecAvailable`).
- Removed: the DV output toggle and its popover case, the DV Deck source (menu, sheet,
  session branch), the bus-codec sections of `playback`/`ui`/`audit`. A saved DV Deck
  in preferences is skipped on load and nothing else is lost (new test).
- `ISF` and the feedback-send check read the end of bus ONE (`busOutputSlot`,
  `dataBurnOneSlot`) where they read `data.one`.
- The corruptor card is "MPEG · corruptor" (saved by module ID, so templates keep it).

### A2 — Every SD clip on the SD canvas was soft (FIXED, `c5786d9`)

`CanvasGeometry.decodeSize` works in square pixels, so a 720×480 4:3 stream on the
720×480 canvas was decoded at **640×480** and stretched back by the GPU — fewer decoded
pixels than canvas pixels, against the function's own rule. It hit MPEG-2 (the wedge)
and any SD .mov. DV had its own decoder and hid it; the refactor's tests caught it as
640×480 frames. A source that needs no reduction now decodes as stored. HD is unchanged
(854×480 for 1080p).

### A3 — DV footage could not be added at all (FIXED, `c5786d9`)

`dv` was dropped from `ImportScan.playableExtensions`, which gates drag-and-drop, Clip
Pads and Import mode. AVFoundation opens .dv fine (checked), so .dv is back as ordinary
video — no bitstream effects, no "DV" wedge badge.

### A4 — DV clips sat in the SD canvas with bars, slightly squeezed (FIXED, `de926a5`)

Through AVFoundation a .dv reports the ITU 10:11 pixel aspect, which on the full 720
raster computes to 1.364 rather than 4:3. `selfqa bars`: "a 4:3 clip's monitor has no
bars — 2 bars". A tagged SD raster now snaps to 4:3 or 16:9
(`CanvasGeometry.displayAspect(width:height:pixelAspect:)`), shared by both decoders.

### A5 — Import mode touched the file system on the main thread (FIXED, `de926a5`)

The From: `NSPathControl` resolved every path component's icon synchronously each time
the header refreshed — every checkbox tick, every listing update. Measured in isolation:
~10 ms cold, ~1 ms warm, more on a card or share. `show()` read 11.3 ms against its
5 ms bar and the import stretch 36.4 ms against 25. The items are now built on the
view's list queue once per folder: `show()` 0.46 ms, stretch 16.1 ms. This is also the
"36.7 ms on the first run after a build" in the backlog.

### A6 — Preview pacing in `push-fade` is borderline (OPEN)

Held-2 fraction 86.7%, 94.5%, 95.2%, 94.9% against a 95% bar over four runs; `stress`'s
wipe pacing passes at 99%. Every pushed frame is exactly on its curve (the picture is
right; the preview's present timing is uneven). Measured with a second Videoboy
presenting to the same display, so not yet attributable. Re-run alone.

### A7 — Smaller frame-path items

- **FIXED:** a burned-in scope made a new texture on the tick at each refresh (6/s per
  bus); it reuses a `TextureUploader` now.
- **FIXED:** the generic "corruptor damages PRIMARY" checks used MPEG mode 0 (frame
  drop), which only skips ahead — a different frame, not a damaged one. They use
  motion-vector mode now, which shows real damage (checked by eye).
- **FIXED:** the soak's memory check judged two endpoints of a sawtooth (a 3-minute run
  read +3.4 MB/min with 0 leaks). Trough to trough now; under 4 settled minutes it is a
  note and `leaks` is the judge.
- **OPEN:** DATA BURN redraws its text on the CPU every frame (timecode): p95 9.8 ms with
  burn on vs 6.6 off. Within budget.
- **OPEN:** the first AVFoundation open in a process costs ~70 ms (`decode` blames
  `bars.dv` because it goes first; `motion.dv` next opens in 5.8 ms). Off the main
  thread since F9.
- **KNOWN (L3):** `audit` fails only on the five emulated-titler faders that bypass the
  registry. Needs FS-UAE to verify a fix.
- **KNOWN (L4):** the native titler still allocates per frame; it is still unwired.

### Read by hand — no finding

- Timers, event monitors and observers: all `[weak self]` and torn down in `deinit`.
- Stored callbacks: none captures `self` strongly.
- Growable buffers: the log ring (512), tap tempo (4), scheduler subscriptions, the MIDI
  queue (drained each tick), the MPEG frame cache (32), the thumbnail LRU (64 MB).
- No `waitUntilCompleted` in a live node (only the `_Template` example).
