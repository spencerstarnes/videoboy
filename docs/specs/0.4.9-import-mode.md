## Rules
- **Nothing on the main thread** but UI: listing a source, duplicate detection, probing
  dimensions for badges and the transfer all run on background queues; the grid fills
  when a listing arrives. Posters come from `ClipThumbnails` (already off-main).
- Greying (never hiding): ADD → destination + optimize disabled; MOVE → destination
  enabled, optimize disabled; COPY → destination enabled, optimize disabled "coming in
  0.4.10". Move disabled (segment greyed) for sources where `allowsMove` is false.
- Import goes through `ImportJob` → `LibraryModel` → `Catalog`. The viewer's player is
  paused when Import mode is left and never touches `Engine`.
- DUP: the file's standardised path is already in the library, or a library clip has
  the same file name and byte size. "Skip duplicates" (on by default) leaves them out.

## Self-QA `import-mode` — asserts (scratch folders, scratch catalog, never the person's)
1. A source folder of fixtures lists in the grid, off the main thread (listing call
   returns < 5 ms; tiles arrive later), with the right count.
2. Badges: `.dv` / `.m2v` wedge-ready; a 16:9 HD fixture ⚠16:9.
3. Greying: per method, destination and optimize enabled states match the table;
   Optimize is disabled in every method; Move is disabled for a read-only source.
4. **Add** end to end: catalog has the clips at their original paths; files untouched.
5. **Move**: files now at destination, gone from source; catalog paths are destination.
6. **Copy**: files at destination and still at source; no `.videoboy-partial` left;
   catalog paths are destination.
7. DUP: after Add, the same folder shows every tile DUP; importing with skip-duplicates
   adds 0.
8. The main thread never stays busy > 25 ms while importing (run-loop observer).
9. The viewer: double-clicking a tile loads it into the viewer's own player; the engine's
   channels are unchanged.
