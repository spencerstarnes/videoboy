# 0.4.10 — Copy + Optimize, linked optimized media

Plan of record: `docs/PROPOSAL-2026-09-26.md` §5 ("Copy + Optimize: linked optimized
media"), §7 (formats, presets, licensing), §9 (phase 4). Behind `FeatureFlag.modeBar`
(it lives in Import mode) plus Settings ▸ Optimize.

## Decision: the helper is Videoboy itself, not an ffmpeg CLI
§7 planned a separate LGPL `ffmpeg` command-line build. Not needed: the app already
links an LGPL libav with the **DV and MPEG-2 encoders** (`DVEncoder`, the streamer),
and macOS decodes every source format (AVFoundation / VideoToolbox, including
HEVC/ProRes that the bundled libav cannot). So the helper is the app's own binary run
as a child process: `Videoboy --optimize <in> <out> <preset>`. Out of process (a
crash cannot take the show down; cancellable), background QoS, no new dependency, no
rebuild of `vendor/ffmpeg`, nothing GPL. THIRD-PARTY.md unchanged.

## What it writes (canvas: SD NTSC 720×480 @ 29.97, the only canvas until 0.4.11)
| Preset | Output | Notes |
|---|---|---|
| **Performance** (default) | raw DV (`.dv`), 25 Mb/s | keeps the DV wedge |
| Compact | MPEG-2 elementary stream (`.m2v`), GOP 6, no B-frames, 6 Mb/s | keeps the MPEG wedge |
| Custom | — | present, disabled, "coming" |
Pictures are FIT into 4:3 (letterboxed/pillarboxed, never stretched), conformed to
29.97 by time (a 25 fps clip repeats frames; a 60 fps one drops them). No audio.

## Linked, Resolve-style
The copied original stays the library's clip (marks, bins). The optimized file goes to
the **Optimized Media location** (`Preferences.optimizedMediaLocation`) and is linked in
the catalog (**migration 2**: `optimized_path`, `optimized_canvas`). Written to
`<location>/.videoboy-partial/` and renamed into place only when complete; the link is
recorded only then. **Use optimized media if available** (Settings ▸ Optimize, default
on): `loadClip` plays the optimized file when it exists and was made for the current
canvas; otherwise the original — never black. A failed conversion is reported in the
status strip and the clip keeps playing its original.

## Self-QA `optimize` (scratch folders + catalog)
1. Core: a 1080p H.264 → DV is 720×480 NTSC DV, frame count = duration × 29.97 (±2),
   the 16:9 picture letterboxed (black top/bottom rows, picture in the middle); a 25 fps
   clip conforms to 29.97; MPEG-2 output decodes through `MPEGStreamDecoder`.
2. Copy + Optimize from Import mode: originals copied; optimized files appear in the
   optimized location; no `.videoboy-partial` left; the catalog links them.
3. Loading the clip plays the optimized file; with the preference off, the original;
   with the optimized file deleted, the original (no black, no error modal).
4. Cancel mid-conversion: no partial file, no link, the queue empties.
5. The show does not notice: 4 channels live while optimizing → 0 dropped frames beyond
   baseline, no tick over a frame.
