# Audit — performance, library, interface (2026-09-23)

Branch `perf/audit`. A pre-audit snapshot lives in `../videoboy-perf-backup`
(branch `backup/perf-audit-2026-09-23`, identical working state incl. uncommitted work).

Method: measured, not guessed. A new check, `scripts/selfqa.sh stress`, opens the real
main window, loads all four channels (bars.dv, motion.dv, motion.m2v, motion.mov),
switches every effect on with non-neutral settings, runs the transport, and times the
WHOLE display-link tick (graph + UI) for 8 s on a **release** build. Per-node cost is
profiled inside the graph. The existing jitter check in `selfqa ui` times the graph
alone, offscreen, with two channels — which is why it never saw the problems below.

Status key: **FIXED** (done + retested) · **OPEN** (recommended, not done — reason given)

---

## Performance under load

Baseline (release, 60 Hz display, full load): **30 ticks/s, 238 of 240 refreshes
dropped, mean tick 19.7 ms, worst 36.6 ms** — the worst tick exceeded even one SD frame
(33.4 ms), so the output dropped frames, not just the previews.

| # | Finding | Evidence | Status |
|---|---|---|---|
| P1 | Every effect pass did `commit()` + `waitUntilCompleted()` — ~30 CPU↔GPU round trips a frame at 0.3–0.6 ms each for microseconds of shader work. CLAUDE.md named this as the first thing to attack if jitter appeared; it had. | per-node profile: ~11 ms of 19 ms was waiting | **FIXED** — passes commit without waiting (`MetalContext.submit`); the engine fences ONCE per frame (`waitForIdle`), preserving "every texture is finished when the graph returns". All passes share one queue, so ordering is guaranteed by Metal. Fallback: `VIDEOBOY_SYNC_EVERY_PASS=1`. |
| P2 | Seven preview `CAMetalLayer`s presented vsync-synced; each `nextDrawable()` blocked the render tick until the display freed a drawable. | after P1, tick pinned at exactly 16.3 ms (one refresh), still 30/s | **FIXED** — in-window previews present without vsync (the window server composites at vsync anyway). The OUTPUT window keeps vsync: it feeds the analog chain. |
| P3 | Sources, bus codec, capture and emulated titler allocated a fresh 1.38 MB texture per frame (~165 MB/s through the GPU allocator at 4 × 30 fps — the long-show fragmentation pattern already fixed once for readback) and swizzled R/B in a CPU per-pixel loop. | source nodes 1.8–2.4 ms each | **FIXED** — `TextureUploader`: two alternating reused textures + Accelerate SIMD swizzle. Pixel-exact vs the old path (`TextureUploaderTests`). |
| P4 | The graph renders at the DISPLAY rate (60 Hz here, 120 Hz ProMotion) though content is 29.97: every other tick re-renders an identical frame. Worse, echo/feedback step once per render call, so trail decay and feedback delay depend on the monitor — 2× too fast at 60 Hz, 4× at 120 Hz. | `EchoNode` swaps buffers, `FeedbackNode` advances its ring, per `render` | **FIXED** — the render clock is paced at the content rate (30 Hz). Halves the load; effect timing now identical on every display. **Behaviour change:** echo trails/feedback are longer than they looked on a 60 Hz screen — they now match 29.97 as designed. Revert: `VIDEOBOY_RENDER_AT_DISPLAY_RATE=1`. |
| P4b | **Clips played at 2× speed on a 60 Hz display (4× on 120 Hz ProMotion)** whenever the app kept up with the refresh — `ClipSourceNode` advances one frame per render, and the graph rendered per display refresh. Hidden until now only because load held the loop at ~30/s. | `advancePlayhead(by: sourceFramesPerProjectFrame)` per `render` | **FIXED** by P4: the engine renders once per 29.97 content frame (`Engine.contentFrameDue`), exact on any display rate. |
| P7 | **Hiding, minimising or covering the main window froze the output.** The render clock was the main window's view display link, which stops when its window is off screen — and the same loop feeds the output window. Hidden: 0 frames in 4 s. Covered: a 954 ms stall (a starved preview `nextDrawable()` hitting its 1 s timeout). | new hidden-window phase in `selfqa stress` | **FIXED** — engine clocks from a SCREEN display link (re-attached when the window changes screen), App Nap exempted while running; previews skip presenting when their window isn't visible. Hidden: 120 frames in 4 s. |
| P5 | Occasional single-tick spike (~19 ms) remains, in source decode on the main thread. | worst tick after P1–P3 | **OPEN** — the structural fix is decoding the next frame on a background queue (prefetch). Worth doing, but it is concurrency on the frame path and should be its own reviewed change. Now inside budget either way. |
| P6 | `selfqa ui` jitter check measures graph-only with 2 channels, budgeted at 33.4 ms, while the live loop ran at display rate with UI on the same thread; CLAUDE.md's "11.4 ms worst" was stale. | — | **FIXED** — `selfqa stress` is the load test of record; CLAUDE.md updated with the measured numbers and the rule to use it. |

After P1–P4 (release, full load): see "Retest" below.

## Library handling

| # | Finding | Status |
|---|---|---|
| L1 | `LibraryModel.add` de-duplicated by **file name**: `Reel A/CLIP0001.dv` and `Reel B/CLIP0001.dv` — the normal case for camera cards, and exactly what the recursive folder drop produces — kept only the first, silently. | **FIXED** — de-duplicates by file path; name only for items with no URL. |
| L2 | The Asset Browser's search field is on every tab but only filtered **Clips**. | **FIXED** — every grid tab filters by the same rule (name, badge, bin). |
| L3 | Empty Clips grid said "No media in samples/. Drop files there and re-run scripts/make-fixtures.sh." — developer text, and shown even when a search simply matched nothing (reads as "your library is gone"). | **FIXED** — "No clips match “…”" while searching; "Drop clips or folders here" when truly empty. |
| L4 | `selfqa ui` "library search actually filters" failed while search worked live: it counted item views inside HIDDEN grids (e.g. list style), and the paired "clearing restores" check passed trivially. | **FIXED** — counts only visible item views, and records a FAIL instead of silently skipping when there is nothing visible to search. |
| L6 | The library's deferred grid rebuild used `DispatchQueue.main.async`, which a nested `RunLoop.run` does not drain — in the harness the search never rebuilt and a stuck `rebuildScheduled` flag swallowed every later rebuild in that panel. | **FIXED** — scheduled on the run loop (`RunLoop.main.perform`), identical live. |
| L5 | Items are identified by NAME for bin moves/drag, so after L1 two same-named clips are ambiguous to `moveItem(named:)`. | **OPEN** — needs a stable item ID threaded through the grid, list and pasteboard; larger than a fix-in-passing. |

## Interface quirks

| # | Finding | Status |
|---|---|---|
| U1 | Custom performance keys (CUT/FADE/BEAT, step keys) ignored the first click into an inactive window — it only activated the window. Reproduced live. | **FIXED** — `acceptsFirstMouse` on `VBOptionButton` and `VBStepButton`. |
| U2 | The main window restored to a frame mostly OFF-screen (observed y=753, h=998 on a 1080-pt display after a second display appeared). Autosave does not clamp to the current arrangement. | **FIXED** — on launch the restored frame is fitted to the visible screen it overlaps most. |
| U4 | `selfqa audit` flagged the tap-tempo field and the three BLEND buttons as "enabled but unwired" (stale since 09-19). False positives: closure-driven controls that never declared themselves. | **FIXED** — both conform to `AuditableControl`, reporting wired only when their closures are set. Audit 10/10. |
| U3 | Button ⌥⌘ tap automation: rate key was hidden in the peripheral row, no pre-click highlight, and the row reflowed when armed. | **FIXED** (this session) — pulses with the faders while ⌘⌥ is held; rate key floats above its key; nothing moves (asserted in `selfqa ui`). |

## Build & tooling

| # | Finding | Status |
|---|---|---|
| B1 | App compiles Core as a path dependency; SwiftPM's cached build manifest did not notice a NEW Core file, so the app build failed ("cannot find 'X' in scope") while Core built fine — and a failed build leaves the OLD app in `build/`, so a following self-QA silently measures stale code. | **FIXED** — `build.sh` passes `--disable-build-manifest-caching` for App (~1 s). |
| B2 | `xcode-select` points at CommandLineTools, so editor/SourceKit shows false errors (SDK/compiler mismatch). Scripts are unaffected (they set `DEVELOPER_DIR`). | **OPEN** — needs `sudo xcode-select -s /Applications/Xcode.app` by the owner. |
| B3 | Builds run from a sandboxed/agent shell cannot see the signing keychain and fall back to ad-hoc, voiding Screen Recording (build.sh warns). | **OPEN** — owner re-runs `scripts/build.sh` from a normal terminal before using EMU capture. |
