# Game plan — 2026-10-21

Owner-requested 2026-10-21: "Consolidate all reactions into new features and a game
plan for attacking it." This file merges three reviews written on 2026-10-19/21:

1. the review of `docs/REWRITE-PLAN-2026-10-19.md` (corrections folded in below),
2. what a **DJ** needs to run Videoboy in a booth, hands on the decks,
3. what a **video artist performing with a live band** needs on stage.

It is written for an autonomous Claude Code run. **It is the order of record for the

## 1. What the reviews found, in one page

**The foundation is sound and the shell is not.** `Core/` holds up: bounds-checked
parsers, 915 tests, frame-path invariants that hold in the code. The problems are the
gate (it reports green when it should not), data loss in the catalog and show file,
a 3,965-line `ShellController`, and synchronous GPU readback on the tick for
recording and streaming.

**The wedge does not work in the running app.** The bitstream corruptor is off by
default (`FeatureFlags.defaultsForPhase` in `Core/Sources/VideoboyCore/VideoboyCore.swift`), and when on, the
scheduler's beat reseed is overwritten on the next frame by the registry's default
seed (`ClipSourceNode.swift:876`). The product's thesis is currently false.

**Both performers hit the same wall: the clock.** The only tempo sources are
internal, tap and audio detection (`Engine.swift`, `enum ClockSource`). Detection
needs about 2 s to lock and 15–25 s to recover from a half-time lock, and lands 78%
of beats on the right frame (`docs/BEATNET.md`). `MIDIInput` drops every system
message, so MIDI clock never arrives (`MIDIInput.swift`, `decode(word:)`). There is
no typed BPM, halve, double, nudge, resync or picture-delay offset. Bars and downbeats
are not used anywhere.

**Neither performer can leave it alone.** There is no blackout, no handling of a
display disappearing (no `didChangeScreenParametersNotification` observer in the App
target), autosave defaults to never, nothing reopens on launch, and the audio input
is the system default device only (`AudioInput.swift:34`). ROLL/ADV automate the
sub-mix faders only; the program fader needs a hand.

**Neither performer can move through a show.** The Setlist proposal
(`docs/PROPOSAL-2026-09-28-setlist.md`) is the right design and only its LOCK phase
has shipped. Its song trigger is Apple Music only.

**What is different between them.** A DJ wants the video to follow the decks and run
itself: sync from the DJ software or players, autopilot on bars, a blackout. A band
performer is playing the video as an instrument: sync from the playback rig's MIDI
clock, macros for one-hand builds, LED feedback in the dark, and a GO key per song
section. Everything else is shared.

## 2. Rules for the executing agent

These replace the rewrite plan's rules.

- **Run shape.** Follow `CLAUDE.md` workflow rule 1: keep going across phases in one
  run. Stop only at a phase marked **STOP** below, at an unanswered **DECISION**, or
  on a `CLAUDE.md` rule-5 blocker. (This resolves the rewrite plan's "one phase per
  run", which contradicted `CLAUDE.md`.)
- **Queue.** Before starting a phase, append it to `docs/QUEUE.md` *Queued* as
  "Game plan phase <id> — <title>", quoting this plan's goal line, then move it to *In
  progress*. Move it to *Done* only with the commit hash and the checks run. Work
  that needs hardware or the owner to confirm goes to *Awaiting verification* and the
  run continues with the next phase.
- **Order.** Work the table in §3 top to bottom. Update its Status column in the same
  commit that finishes a phase.
- **Done means.** `scripts/verify.sh` exits 0 on a release build, the phase's named
  self-QA checks pass, and evidence is pinned under `selfqa/out/plan/<phase-id>/`.
- **Commits.** Buildable, one or more per phase, never one commit spanning two phases.
- **Frame path.** The `CLAUDE.md` frame-path invariants are hard constraints. If a
  change makes `selfqa stress` worst tick worse than the baseline R0 pins, it does not
  ship, or it ships behind a flag that is off.
- **Layout.** No existing control moves. `selfqa ui` checks positions, and R0 adds a
  layout dump that must stay byte-identical. **New performance actions go in a new
  Perform menu in the menu bar, a hot key, a MIDI-mappable code and a status-strip
  readout.** A new visible key on the grid is a DECISION for the owner, never a
  judgement call (see §5).
- **Where new code goes.** Logic in `Core/` with unit tests. App wiring in new files
  under `App/Sources/Videoboy/UI/` or `Platform/`, one controller per feature.
  `ShellController.swift` gets at most a construction line and a `refresh` call per
  feature. Do not grow the god object that R3 has to empty.
- **Param codes.** Every new action and parameter gets a permanent code in
  `ParamCode.swift`, allocated per the numbering scheme in its header (mixer and
  transport live in the `6x` block; `6EA`, `6FA`, `6EJ`, `6FJ` are free at
  `450156c`; open a new suffix letter when those run out). Never reuse a code or one
  of the retired codes listed in the header.
- **Network.** `CLAUDE.md` forbids runtime network except where a phase says so.
  Phase P3 says so, for **local-network** clock and track data only, and only while
  the performer has chosen that source. No internet traffic, ever. Add
  `NSLocalNetworkUsageDescription` to the bundle's Info.plist or macOS blocks the
  socket without a prompt.
- **Licensing.** FFmpeg stays LGPL. Anything GPL runs out of process (the DVC100
  tool is the pattern). Protocol implementations are written from published protocol
  descriptions, never translated from another project's source, unless that
  project's licence has been read and recorded in `docs/THIRD-PARTY.md` first.
- **Hardware.** Never claim a `[HARDWARE]` path works without the owner confirming it.
  Build behind a protocol with a mock, test against fixtures, mark the item *Awaiting
  verification*, and continue.
- **Scope.** Anything found that is not in this plan gets one line in the
  `docs/BUILD-PLAN.md` backlog and is not built.
- **No** Apple Developer Program, notarization or distribution signing.

## 4. Phases

### R0 — Make the gate honest (amended)

Run the rewrite plan's R0 with these changes.

1. **Two kinds of BLOCKED, not one.** Today ~100 checks call
   `finish(blockedReason:)` for missing Metal, missing DVC100, missing samples, or a
   flag. If `verify.sh` failed on every BLOCKED it would fail on every machine without
   the full analog chain. Add `SelfQAVerdict.skipped` (or a `kind` on blocked):
   - **environmental block** — hardware, permission, OS version. Allowed in the gate.
   - **section skip** — a software reason a section did not run. Fails the gate.
   `check.skip(reason:)` produces the second kind. Convert the 16
   `check.note(... "skipped")` sites (`grep -rn 'note(.*[Ss]kipp' App Core`) to it.
   Missing samples are not environmental: `verify.sh` runs `scripts/make-fixtures.sh`
   first, so a missing fixture after that is a failure.
2. **Audit faders.** `selfqa audit` passing requires wiring or removing the five inert
   emulated-titler faders. That is product code, and it is allowed in R0 for that
   change only.
3. **Self-test evidence.** `SelfQAHarnessTests` deliberately writes
   `phase-0/empty-check-self-test` (FAIL) and `phase-0/blocked-check-self-test`
   (BLOCKED) on every `swift test`. Point those two at a temporary directory instead
   of `selfqa/out`. The two soak `result.txt` files have no `verdict:` line; give the
   soak check one.
4. **A stress baseline the check reads.** Write `selfqa/baseline/stress.json` (mean,
   p95, worst, ticks over 16 ms, on SD fixtures and on the HD soak clips) from this
   phase's run. `selfqa stress` compares against it and fails if worst tick regresses
   by more than 2 ms. Every later "no worse than pinned" refers to this file.
5. **Layout dump.** Add `selfqa/out/ui/layout.json`: every control's identifier and
   frame, written by `selfqa ui`. Pin it. R3 and every P phase compare against it.
6. **Quick and full gates.** `scripts/verify.sh` is the full gate at phase end.
   `scripts/verify.sh --quick` is build, Core tests, lint and `selfqa ui`, for the
   per-commit loop. Without this, R3's one-extraction-per-commit rule costs a
   fifteen-minute gate per commit.
7. Everything else in the rewrite plan's R0 stands: lint passes `FFMPEG_FLAGS` so the
   warning build actually compiles, `warnings.sh` runs from `verify.sh`, the titler
   pointer-lifetime warning is fixed properly, the added checks (`stress`, `midi`,
   `audit`, `template`, `mosh`, `undo`, `lock`, `push-fade`) join the gate, stale
   FAIL evidence goes, Q1 and Q2 are verified and ticked.

**Acceptance.** The rewrite plan's R0 acceptance, plus: `swift test` leaves no FAIL or
BLOCKED `result.txt` under `selfqa/out`; `stress.json` and `layout.json` are
committed; `verify.sh --quick` exists and exits 0.

### P1 — Booth basics

Goal: a performer can set and correct tempo by hand, black the screen, take audio
from a mixer, and reach every booth action without the mouse.

1. **Perform menu.** A new menu-bar menu holding every action in this plan as it
   lands, each with a default key equivalent, editable in Settings ▸ Hot Keys
   (`Preferences.hotKeys`), and each backed by a param code so MIDI learn reaches it.
   Text fields keep their keys; menu equivalents never fire while one is editing.
   New file: `App/Sources/Videoboy/UI/PerformMenu.swift`.
2. **Tempo controls.** In `Core/.../Clock/Transport.swift` plus a small App
   controller:
   - typed BPM: double-click the tempo field (`VBTempoField.swift`) to edit, Enter
     commits, Esc cancels, clamp 40–240;
   - **×2** and **÷2**;
   - **NUDGE −/+**: shift phase 10 ms per press through `shiftPosition(byBeats:)`,
     repeating while held;
   - **RESYNC**: the next press is bar 1 beat 1 (shifts position so the press's
     presentation time is a bar line);
   - **TAP** as a mappable action if it is not one already.
   In audio-sync mode a manual tempo or phase change holds until the tracker relocks
   at a clearly different tempo; it does not get overwritten next report.
3. **Picture delay.** Settings ▸ Inputs ▸ "Picture delay" in ms (−100 to +200),
   added to the scheduler's latency compensation (`Scheduler.swift`, `T − latency`)
   so beat-locked events land early enough to cover a projector or LED processor.
   It applies to every clock source. This closes the "screen latency uncompensated"
   item in `docs/BEATNET.md`.
4. **BLACK.** A program-stage node after the program mix and before output emulation:
   - takes program to black on the current quantise (cut, beat, bar), with the
     `FadeAutomation` curves, and back again on the next press;
   - black is the canvas's legal black, the same level the broadcast-safety check
     uses, so the analog chain never sees an illegal level and sync is untouched;
   - optional **hold still** instead of black: Settings ▸ Defaults picks an image
     (band name, venue slide), uploaded once when chosen, never per frame;
   - early-returns when off, like every node; recording and streaming see what the
     audience sees;
   - status strip shows "BLACK" while held.
5. **Audio interface input.** Add `case device(uid: String, name: String, channels:
   ClosedRange<Int>)` to `AudioCaptureSource` (`AudioInput.swift:32`). The CLOCK menu
   lists every input device and a channel pair (a mixer's record out is often on
   3/4). Show input peak level and a clip warning above −1 dBFS in the sync readout.
   Persist by UID. If the device is missing at launch, fall back to Internal with a
   status-strip notice, never silently to the built-in microphone.
6. **Ready check.** The top of the Perform menu shows live, disabled status lines:
   output display and negotiated mode, clock source and lock state, MIDI devices,
   autosave cadence and last save, recording disk free. One glance before doors, no
   new window.

**Acceptance.**
- Core tests: typed tempo clamps; ×2/÷2 keep phase; RESYNC puts the press time on a
  bar line; nudge moves phase by the stated amount; picture delay shifts a scheduled
  event's fire time by exactly that delay.
- New `selfqa perform`: every Perform menu item exists, has a key and a code, and
  fires its action through `NSMenu.performActionForItem`; a MIDI learn round-trip on
  BLACK through `VirtualMIDISource`; BLACK on and off renders a black PNG at the
  legal level and returns to the picture; a scheduled cut with picture delay 100 ms
  fires 100 ms earlier.
- Layout dump unchanged. `selfqa stress` with BLACK engaged and released no worse
  than baseline.
- Audio interface: unit test the device list through a protocol mock; the owner
  confirms with the real interface (*Awaiting verification*).

### P2 — Survive the venue

Goal: a crash, a relaunch or a projector power cycle does not need the mouse.

1. **Autosave on by default.** Default `AutoSaveCadence` becomes `everyFiveMinutes`
   for new preference files. Existing files keep the owner's explicit choice.
   Autosave uses R1's atomic write and never runs on the tick.
2. **Clean-quit sentinel.** Write a sentinel in Application Support at launch and
   remove it at clean quit. If it is present at launch, reopen the newest autosave and
   say so on the status strip ("Did not quit cleanly; reopened <show> from 21:14").
   No modal.
3. **Reopen at launch.** New preferences, default on: reopen the last show, open the
   output window on the configured display if present, restore the last clock source
   (not just `defaultClockSource`). Document a `launchd` KeepAlive agent in
   `docs/FIRST-RUN.md` for relaunch after a crash; do not install it.
4. **Display hot-plug.** Observe `NSApplication.didChangeScreenParametersNotification`
   in `DisplayRouter`:
   - the configured output display (by name from `config/devices.json`) disappears:
     close its output window cleanly, never move program onto the performer's screen,
     status strip says "Output lost — waiting for <name>";
   - it returns: reopen on it within 2 s and log the negotiated mode;
   - **the render clock is a screen display link.** If its screen is the one that
     left, rebind it to a remaining screen before the window closes. The picture on
     every other output and the recording must not stop.

**Acceptance.**
- Core tests for the display-selection logic behind a screen-list protocol.
- New `selfqa hotplug`: fake screen list, remove and restore the output screen by
  posting the notification. Assert the output window closes and reopens on the right
  screen, no tick gap over two frames, recording frame count continuous.
- `selfqa template` round-trips the new preferences.
- **Owner:** pull the output HDMI mid-show and plug it back; force-quit and relaunch.
  *Awaiting verification*; the run continues.

### P3 — External clock

Goal: tempo and phase come from the DJ software, the players or the band's playback
rig, not from a microphone.

**One follower for every source.** New `Core/.../Clock/ExternalClockFollower.swift`.
It takes timestamped beat information from any source and drives `Transport` through
one path:
- tempo from a least-squares fit over the recent window, published once stable;
- phase locked with a slew limit: a correction under 1/8 beat is slewed over a beat,
  a larger one snaps on the next bar line, so the picture never jumps mid-phrase;
- bar position taken when the source carries it;
- **source lost**: freewheel at the last tempo, status strip "MIDI clock lost —
  holding 128.0", never stop the picture.
`Engine.ClockSource` gains a case per source. The CLOCK menu lists only sources that
are actually present.

**P3a — MIDI clock in.** Build first; it covers Ableton, Traktor, Serato, Logic and
every band playback rig.
- Decode UMP system real-time and common messages in `MIDIInput.decode(word:)`:
  clock (`F8`), start (`FA`), continue (`FB`), stop (`FC`), song position (`F2`).
- **Timestamp from the packet** (`MIDIEventPacket.timeStamp`, host time), not arrival
  on main. Clock ticks bypass the main-thread drain and go straight to the follower,
  which is lock-protected and read in `onBeforeRender`. Main-thread jitter would
  otherwise be the tempo error.
- Start resets to bar 1 beat 1; song position sets the bar; stop follows the
  existing transport-stop behaviour.
- **Acceptance:** follower unit tests with synthetic ticks: steady 128 BPM with ±1 ms
  jitter within ±0.1 BPM after two beats and phase within 2 ms; a ramp 120→126 over
  eight bars tracked within 0.3 BPM; ticks stopping gives freewheel. New
  `selfqa midi-clock` through `VirtualMIDISource`: same three cases end to end, a
  scheduled cut lands on the beat frame, 0 dropped frames.

**P3b — Pro DJ Link (Pioneer CDJ and XDJ, rekordbox performance mode).**
- Passive only: listen for beat packets on UDP 50001, which players broadcast while
  playing. They carry pitch-adjusted tempo and beat-within-bar. Do not join the
  network as a virtual player in this phase.
- Follow the tempo master when it can be identified passively, otherwise the player
  chosen in the CLOCK menu.
- Implement from the published DJ Link packet analysis. Deep Symmetry's beat-link
  and dysentery are EPL-licensed; do not translate their source.
- **Acceptance:** parser unit tests against fixtures built from the documented layout
  and marked synthetic; follower tests as in P3a. `[HARDWARE]`: owner confirms with
  two players on a switch. *Awaiting verification*.

**P3c — StagelinQ (Denon Engine OS players and controllers).**
- Discovery on UDP 51337, then the device's BeatInfo service for per-deck beat,
  total beats and tempo; follow the master deck.
- Read each reference implementation's licence before reading its code; record it in
  `docs/THIRD-PARTY.md`. Prefer writing from protocol notes.
- **Acceptance:** as P3b. `[HARDWARE]`.

**P3d — Ableton Link. DECISION D1 before starting.** Link is the most common sync in
DJ software, but its SDK is GPL-2.0-or-later with a paid proprietary licence as the
alternative. The recommended path is an out-of-process helper (`tools/videoboy-link`,
built from the SDK, spawned like the DVC100 tool) that reports tempo, beat, phase and
peer count at host time over a pipe. That keeps the app's licence intact, but the
helper itself must ship with its source. If the owner has not answered D1, skip P3d,
leave it *Queued*, and continue.

### P4 — Bars, phrases and program AUTO

Goal: changes land on bar one and phrase boundaries, and the program fader can run
itself.

1. **Bar phase.** Sources that carry bar position set it (song position, DJ Link
   beat-in-bar, StagelinQ, Link with quantum 4). RESYNC sets it by hand. With audio
   detection, vote with BeatNet's downbeat activation
   (`BeatNetTracker.lastActivation.downbeat`, currently unused): accumulate per
   beat-in-bar slot over eight bars and adopt the winner when its margin is clear.
   Show "bar ?" until bar phase is known.
2. **Quantise to bars.** Add 1, 2, 4 and 8 bars to `Subdivision`
   (`Transport.swift:38`), relative to `beatsPerBar`. CUT, FADE, pads, flips and BLACK
   honour them.
3. **Program AUTO.** Off by default, saved in the show.
   - Every N bars (4, 8, 16, 32; default 8), on the bar line, program takes to the
     other bus with the current take style (CUT, or FADE at the current rate).
   - When a bus leaves program, its sub-mix cuts to its other channel off air, so the
     existing ROLL/ADV rules refill it (`docs/specs/ab-roll-adv.md`). With ADV off it
     only flips.
   - A manual program take restarts the count. Moving the program fader by hand
     pauses AUTO until AUTO is pressed again.
   - A LOCKed bank's sub-mix is never flipped (`BankLock.swift`); program still takes.
   - Status strip: "AUTO 8 bars · next take in 3.2". The visible AUTO key is DECISION
     D2; until then it lives in the Perform menu, a hot key and a MIDI code.

**Acceptance.** Core tests: downbeat voting adopts the right slot on a synthetic
activation stream and abstains on a flat one; bar subdivisions schedule on bar lines;
the AUTO state machine (count, manual-take reset, pause, LOCK). New `selfqa auto`:
174 BPM, N = 4, every take lands on a bar-line frame (presentation time within half a
frame), the off-air sub-mix flips, 0 dropped frames over 5 minutes.

### P5 — Control surface

Goal: a performer in the dark can see state on the controller and move many things
with one hand.

1. **MIDI out with LED feedback.** New `Core/.../Control/MIDIOutput.swift`. A mapped
   note gets its state sent back: on, off, and blinking on the beat for armed or
   pending states. Per-device velocity profiles in `config/devices.json`
   (`midiFeedback`), generic default 127/0, so a Launchpad or APC shows colours.
2. **Macros.** Eight macro codes, each a named control whose value drives a list of
   (target code, min, max, curve). A macro is a target type in the existing mapping
   table, not a second system: MIDI maps to a macro code like any other code.
   Evaluated in `onBeforeRender` at the frame's presentation time. Edited in Settings
   ▸ MIDI Mapping, so the grid layout does not change. Saved in the show as an
   additive optional field; old shows open unchanged.

**Acceptance.** Core tests: macro resolution, curves, round-trip through
`TemplateDocument`; feedback state machine. New `selfqa midi-out`: a virtual
destination receives the right note and velocity when BLACK, AUTO, LOCK and a pad
toggle; a macro moved through `VirtualMIDISource` moves all its targets in the same
frame. `selfqa stress` with eight macros each driving four targets: no worse than
baseline.

### P6 — Setlists with GO / BACK

Goal: move through a show section by section with one key, with the next section
prepared off air.

1. **Fold the decided items from QUEUE Q3** into the proposal before building: GO and
   BACK on ⌘⇧→ and ⌘⇧←, arm then execute (first press arms, second executes), armed
   until executed or Esc, green glow on the receiving bank while armed and a flash on
   execute, BACK always re-prepares, the keys yield to text fields, Space counts as GO
   while a Setlist is running. Keep the proposal's names (Queue, Playlist, Setlist);
   the consult's "Scene" means the proposal's Setlist.
2. **Build the proposal's phases 0, 2 and 3** (`§9`; phase 1, LOCK, shipped) on
   `ShowModel`: Queues saved in the show, Playlists and the Lists tab, Setlists as
   bank-relative snapshots with Punch / Cue / Crossfade start-up.
3. **GO / BACK** walk an ordered Setlist list: GO loads the next Setlist onto the
   off-air bank, and on execute takes program with that Setlist's start-up sequence on
